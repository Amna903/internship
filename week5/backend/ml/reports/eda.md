## 2. Class balance

| outcome | rows | share |  |
|---|---|---|---|
| attended | 16,785 | 83.6% | █████████████████████████ |
| no-show | 3,291 | 16.4% | █████ |

**Imbalanced: 16.4% no-shows.** A model that always says "attends" would be 83.6%
accurate and completely useless.
→ **Use PR-AUC (minority class), ROC-AUC and the Brier score, not accuracy. Choose the decision
threshold on validation data, not 0.5.**

## 3. Missing values

| column | missing | share |
|---|---|---|
| distance_km | 1,547 | 7.7% |

All other columns are complete.

Is missingness linked to the outcome? No-show rate with distance **missing 18.4%**
(1,547 rows) vs **present 16.2%**: a gap of
2.1 points, two-proportion z-test **p = 0.030**.
p < 0.05 would normally count as a real link. But the generator blanks values completely at random, so here it is a false alarm of the kind a 5% test raises about 1 time in 20: one significant test is not proof. Either way, the model gets a missing-value flag (below), so it can use the signal if it is real and will learn to ignore it if not.
→ **Step 3: impute `distance_km` with the median of the training split only, and add a
`distance_missing` flag** so the model could still use missingness if it ever carried signal (in real
data it often does).

Overall no-show rate: **16.4%**. "vs overall" above 1 means riskier than average.

### 6.1 Lead time: a curve, not a straight line

| 0–2 | 4,422 | 7.8% | 0.48× | ██████ |
| 3–7 | 5,426 | 14.7% | 0.89× | ███████████ |
| 8–14 | 4,556 | 18.7% | 1.14× | ██████████████ |

| 31+ | 1,523 | 26.0% | 1.59× | ████████████████████ |

The rate climbs steeply over the first days (7.8% → 18.7% by
8–14 days), then the increase slows down.
→ **A straight-line (linear) effect on raw days misfits this. Engineer `log(1 + lead_time_days)`.**

### 6.2 Reminder × lead time: an interaction

| days ahead | no reminder | reminder | reminder effect |
|---|---|---|---|
| 0–2 | 9.0% | 7.2% | −1.8 pts |
| 3–7 | 15.8% | 14.1% | −1.7 pts |
| 8–14 | 21.6% | 17.1% | −4.5 pts |
| 15–30 | 24.6% | 20.2% | −4.4 pts |
| 31+ | 31.9% | 23.2% | −8.7 pts |

A reminder barely matters for short-notice appointments and matters a lot for ones booked far ahead.
→ **One weight for `reminder_sent` cannot capture this. Engineer `reminder × lead time` (or use a
tree model, which finds interactions itself).**

## 8. Leakage and split readiness

**Single-feature check.** How well each feature *alone* separates no-shows (ROC-AUC; 0.50 = no
signal). A feature above 0.80 on its own would be suspicious: it usually means the column
encodes the answer.

| feature | AUC alone |
|---|---|
| lead_time_days | 0.618 |
| age_band | 0.575 |
| prior_no_shows | 0.566 |
| reminder_sent | 0.527 |
| visit_type | 0.526 |
| distance_km | 0.523 |
| appointment_weekday | 0.522 |
| booking_channel | 0.514 |
| appointment_hour | 0.506 |
| prior_appointments | 0.506 |

Strongest single feature: `lead_time_days` (0.618), well below the leakage threshold.
Excluded from this table and from every model: `appointment_id`, `patient_id`, `true_no_show_probability`.

**Patients repeat.** 95.2% of patients have more than one appointment (mean
4.02). If one patient's appointments landed in both train and test, the model
could score well by recognising the person rather than learning patterns.
→ **Step 3: split by patient (`GroupShuffleSplit` on `patient_id`), 60/20/20, so every patient is in
exactly one of train, validation or test.**

## 9. Bias: age

| age band | rows | no-show rate | vs overall |  |
|---|---|---|---|---|
| 18-24 | 2,709 | 24.7% | 1.51× | ███████████████████ |
| 25-34 | 4,089 | 19.6% | 1.20× | ███████████████ |
| 35-44 | 3,906 | 14.4% | 0.88× | ███████████ |
| 45-54 | 3,674 | 13.7% | 0.84× | ██████████ |
| 55-64 | 3,179 | 12.8% | 0.78× | ██████████ |
| 65+ | 2,519 | 13.7% | 0.84× | ██████████ |

18–24-year-olds miss 24.7% of appointments vs 12.8% for 55–64, i.e.
1.9× as often. Any model trained on this data will flag younger patients more, including
young patients who would have attended (false positives).
→ **Step 5: report false-positive and false-negative rates per age band.** The output may only drive
supportive actions (an extra reminder), never penalties.

## 10. Decisions this analysis supports

| Finding | Decision | Step |
|---|---|---|
| 16% minority class | PR-AUC, ROC-AUC, Brier; threshold chosen on validation | 4–5 |
| `distance_km` 7.7% missing, at random | Median imputation fitted on train only + `distance_missing` flag | 3 |
| Patients repeat across rows | Split grouped by `patient_id`, 60/20/20 | 3 |
| Lead-time effect is a curve | Engineered `log(1 + lead_time_days)` | 4 |
| Reminder effect depends on lead time | Engineered `reminder × lead time`; tree model as comparison | 4 |
| Past behaviour predicts | Engineered `prior_no_show_rate` | 4 |
| No single feature is suspiciously strong | No leakage found in the features | 3 |
| Age bias | Per-age-band error rates; supportive use only | 5 |
