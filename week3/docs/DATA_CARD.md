# Data card: synthetic appointment no-show dataset

> **Synthetic and educational only.** No row describes a real person or appointment. Nothing learned from this data says anything about real clinics or real patients, and it must not be used for clinical decisions.

## At a glance

| | |
|---|---|
| Task | Binary classification: will a fictional appointment be missed (`no_show`)? Not diagnostic. |
| Rows | 20,076 appointments for 5,000 fictional patients (about 4 each) |
| No-show rate | **16.4%** (imbalanced: no-show is the minority class) |
| Missing values | `distance_km`: 7.7% blank; every other column complete |
| Seed | `SEED = 42` in `backend/ml/config.py` |
| Dataset SHA-256 | `f458e62a1442a732194b813a3800bb059c656f164d47d485ad800085557e189e` (canonical CSV, `float_format="%.6f"`) |
| Regenerate | `cd backend && python -m ml.data` → `ml/data/appointments.csv` (git-ignored, rebuilt identically) |

## Provenance

Generated by `backend/ml/data.py`, written for this project. It uses no external data, no real records, and no data derived from real records.

How it's built:
1. Create 5,000 patients. Each gets an age band, a distance from the clinic, and a **hidden reliability** score. That score is never written to the dataset.
2. Give each patient a history of earlier appointments, drawn from that reliability.
3. Create about 4 appointments per patient **in time order**. Each outcome becomes part of the history for that patient's next appointment.
4. Compute each appointment's no-show probability from a known formula (below), then draw the outcome with a weighted coin flip.
5. Blank out about 8% of distances at random.

The **directions** of the effects follow commonly reported no-show patterns: longer lead times, past no-shows, younger age and greater distance raise no-shows, and reminders lower them. The **sizes** of the effects are invented.

## The planted ground truth (log-odds; positive means more likely to miss)

| Effect | Shape | Observed in the data |
|---|---|---|
| Lead time | `0.55 × log(1 + days)`: rises fast, then flattens (a curve) | |
| Reminder | `−0.15 − 0.45 × min(days, 30)/30`: **stronger for appointments booked far ahead** (an interaction) | 30+ days ahead: 28.9% → 18.7% with a reminder; ≤ 2 days: 7.6% → 6.0% |
| Age band | 18-24 +0.60 … 55-64 −0.30 | 21.9% (18-24) vs 10.7% (55-64) |
| Distance | +0.012 per km | |
| Telehealth | −0.35 | |
| Weekday / hour / channel | small (≤ 0.15) | |
| Hidden reliability | per patient, SD 0.6; visible only through the no-show history | |

The curve and the interaction are deliberate. A linear model on raw inputs can't fully represent them, so a better model (engineered features or gradient boosting) has real structure to find. Because the true probability is known, we can also report an **oracle ceiling**: the score of the true probabilities themselves, which no model can beat.

## Class imbalance

16.4% of appointments are no-shows. Consequences for later steps:
- **Accuracy is misleading.** Always predicting "attends" scores about 84% while being useless.
- Models are compared on **PR-AUC** (focused on the minority class), ROC-AUC and the Brier score.
- The decision threshold is chosen on the validation set, not fixed at 0.5.

## Bias

**Age is a planted driver.** Younger patients miss more often, both in this data and by design. Any model trained on it will flag younger patients more often, including some who would have attended (false positives).

**Measured on the chosen model** (validation, threshold 0.169; full detail in
[errors.md](../backend/ml/reports/errors.md) §4):

| | 18-24 | 55-64 |
|---|---|---|
| attenders wrongly flagged (false-positive rate) | 71.8% | 24.0% |
| no-shows caught (recall) | 85.4% | 41.9% |
| appointments flagged | 75.3% | 26.0% |

Removing age (analysis only, not shipped) costs PR-AUC 0.276 → 0.260 and removes most of that gap.

Consequences:
- Error rates **per age band** are reported in the error analysis.
- The prediction may only support **low-cost, supportive actions**, such as an extra reminder. It must never support penalties, refusals or prioritisation.
- In a real system, using age as a feature would need a fairness review. Here it's kept on purpose, to demonstrate measuring bias.

## Limitations

- **Synthetic.** The model can only learn the effects we planted, so its metrics show how well it recovers the formula, not real-world performance.
- **Missingness is completely random.** In real data, a missing distance often *means* something, such as a new patient. Here it carries no signal.
- **No time dimension.** There are no dates, seasons or trends, and the split doesn't follow time.
- **No interactions beyond the one planted**, and no measurement error in the features.
- **Effect sizes are invented**, and the population mix (age and channel shares) is made up.
- **Fixed, closed population**: 5,000 patients, all with prior history.
