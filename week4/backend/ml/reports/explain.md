# Explaining the models: importance and mistakes

> Synthetic, educational data. Generated by `python -m ml.explain`; do not edit by hand. Explanation only:
> nothing here changes a model, and the test set is not used. Everything is on the 3,998
> validation rows. Importance measures what a model relies on, not what causes no-shows.

Served model: `no-show-1.0.0` (logreg_engineered (C=0.1)), validation PR-AUC 0.276.

## 1. Permutation importance of the served model

Each input is shuffled 20 times (seed 42); the column shows how much validation PR-AUC drops
(mean ± sd over the shuffles). Engineered features (log lead time, past no-show rate, reminder × lead
time) are computed from their input inside the pipeline, so they move with it. "Within noise": two
standard deviations reach zero, so there is no evidence the model relies on that input.

| input | PR-AUC drop when shuffled | |
|---|---|---|
| `lead_time_days` | +0.0583 ± 0.0067 |  |
| `prior_no_shows` | +0.0465 ± 0.0083 |  |
| `age_band` | +0.0294 ± 0.0057 |  |
| `prior_appointments` | +0.0138 ± 0.0031 |  |
| `reminder_sent` | +0.0100 ± 0.0039 |  |
| `visit_type` | +0.0060 ± 0.0025 |  |
| `distance_km` | +0.0044 ± 0.0020 |  |
| `appointment_weekday` | +0.0015 ± 0.0023 | within noise |
| `booking_channel` | +0.0014 ± 0.0015 | within noise |
| `appointment_hour` | -0.0000 ± 0.0001 | within noise |

The generator weights lead time, the no-show habit (visible only through prior no-shows) and age band
most. Of these, 3 of 3 rank in the top 4:
`lead_time_days`, `prior_no_shows`, `age_band`.

`age_band` appears here because age is a planted driver of no-shows in this synthetic data. Relying on it
makes the model flag younger patients more often, including some who would attend; that cost is measured
in [errors.md](errors.md) (age bias section).

### Caveat: correlated inputs share credit

Inputs that carry overlapping information can share credit: when one is shuffled, the model still gets
part of the same signal from the other, so shuffling one alone may **understate** its importance. Prior
appointments and prior no-shows are such a pair (the no-show rate is built from both). Shuffling them
**together**, with the same row order so their relationship stays intact, counts their shared credit once:

| group | PR-AUC drop, shuffled together | sum of the two shuffled alone |
|---|---|---|
| history (prior_appointments + prior_no_shows) | +0.0394 ± 0.0062 | +0.0603 |

For history (prior_appointments + prior_no_shows), the opposite happened: the group drop (+0.0394) is smaller than the sum of the single drops (+0.0603). Here the singles **overstate**. The engineered past no-show rate is built from both columns, so shuffling either one alone scrambles it, and its importance is counted in both single drops. A smaller extra effect: shuffling prior no-shows alone creates impossible rows (more no-shows than appointments) in 2.3% of rows, which the model never saw in training. The group drop is the cleaner estimate of how much the model relies on the patient's history.

## 2. Random forest: impurity importance versus permutation importance

The random forest with the best CV score (`random_forest (max_depth=6, min_samples_leaf=20)`), refitted on the train part. **Impurity
importance** (built in) measures how much each input's splits reduce impurity while training; one-hot
columns are summed into their input. **Permutation importance** is computed as in section 1.

| input | impurity importance (sums to 1) | permutation: PR-AUC drop |
|---|---|---|
| `lead_time_days` | 0.214 | +0.0647 ± 0.0066 |
| `appointment_hour` | 0.028 | +0.0012 ± 0.0009 |
| `prior_appointments` | 0.026 | +0.0102 ± 0.0033 |
| `prior_no_shows` | 0.064 | +0.0496 ± 0.0064 |
| `distance_km` | 0.067 | +0.0032 ± 0.0019 |
| `appointment_weekday` | 0.029 | +0.0014 ± 0.0014 |
| `age_band` | 0.133 | +0.0298 ± 0.0045 |
| `visit_type` | 0.033 | +0.0044 ± 0.0023 |
| `booking_channel` | 0.021 | +0.0018 ± 0.0015 |
| `reminder_sent` | 0.015 | +0.0068 ± 0.0021 |
| `log_lead_time` | 0.214 | moves with its source |
| `prior_no_show_rate` | 0.107 | moves with its source |
| `has_history` | 0.000 | moves with its source |
| `reminder_x_lead` | 0.049 | moves with its source |

Known flaw: impurity importance favours inputs with many distinct values, because they offer more
split points even when the splits fit noise. The three continuous inputs (lead time, distance, hour)
hold 31% of the forest's impurity importance. The clearest case here is `distance_km`: 0.067 of the impurity importance, but a permutation drop of only +0.0032. Permutation importance is the measure to trust for reliance; impurity importance shows where the trees found split points.

## 3. False positives and false negatives of the served model

At the served cut-off (0.1688): what each kind of appointment has in common, compared with
all validation appointments.

| | rows | mean lead time (days) | reminder sent | has history | past no-show rate | age 18–24 | telehealth | true no-show probability |
|---|---|---|---|---|---|---|---|---|
| all validation | 3,998 | 11.2 | 64.8% | 98.7% | 14.9% | 12.1% | 24.5% | 16.4% |
| true positives | 383 | 18.3 | 54.3% | 99.0% | 25.7% | 27.4% | 15.7% | 29.8% |
| false positives (attended, flagged) | 1,206 | 17.8 | 62.0% | 98.7% | 21.5% | 21.6% | 15.6% | 22.6% |
| false negatives (missed, not flagged) | 263 | 7.9 | 68.4% | 98.5% | 10.9% | 6.8% | 30.4% | 15.5% |
| true negatives | 2,146 | 6.7 | 67.8% | 98.7% | 9.7% | 4.8% | 30.3% | 10.7% |

- **False positives** (attended but flagged, an unneeded reminder): booked 17.8 days ahead on average (all: 11.2); less often reminded (62.0% vs 64.8%); more often aged 18–24 (21.6% vs 12.1%); past no-show rate 21.5% (all: 14.9%). Their true no-show probability averages 22.6% (all: 16.4%), so the model's call was reasonable: they looked like no-shows and attended anyway.
- **False negatives** (missed but not flagged): booked 7.9 days ahead on average (all: 11.2); more often reminded (68.4% vs 64.8%); less often aged 18–24 (6.8% vs 12.1%); past no-show rate 10.9% (all: 14.9%). Their true no-show probability averages 15.5% (all: 16.4%), so these no-shows were less likely than average: they looked like attenders and missed anyway.

Unavoidable or model mistake? The synthetic data has the true probability, so we can ask whether perfect
knowledge, with the same cut-off, would have made the same call:

| | errors | unavoidable (true probability makes the same call) | model mistakes |
|---|---|---|---|
| false positives | 1,206 | 808 (67%) | 398 |
| false negatives | 263 | 169 (64%) | 94 |

The five most confident mistakes of each kind, with their inputs, are listed in [errors.md](errors.md).
